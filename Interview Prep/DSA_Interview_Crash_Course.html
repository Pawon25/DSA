Java Syntax & Collections

The exact gotchas that bite under interview pressure — several of these came up in your own code today.

ArrayList<T>

List<Integer> list = new ArrayList<>();
list.add(5);            // add element
list.get(0);             // read by index — O(1)
list.set(0, 9);           // overwrite by index
list.size();
list.remove(Integer.valueOf(5));  // removes the VALUE 5
list.remove(0);                    // removes the element AT index 0
Gotcha: list.remove(int) removes by index, but list.remove(Integer.valueOf(x)) removes by value. Mixing these up is one of the most common silent bugs in Java collections interviews — you hit almost the exact same trap today with Set<Character>.remove(int) autoboxing to Integer instead of matching a char.

HashMap<K,V> / HashSet<T>

Map<Character, Integer> freq = new HashMap<>();
freq.put('a', 1);
freq.get('a');                       // null if absent
freq.getOrDefault('a', 0);           // safe default
freq.containsKey('a');
freq.merge('a', 1, Integer::sum);    // increment-or-insert in one line

Set<Character> seen = new HashSet<>();
seen.add('a'); seen.contains('a'); seen.remove('a');
Intuition: reach for HashMap/HashSet the instant a problem needs "have I seen this before?" or "count of X" in O(1) — this replaces an O(n) inner loop with an O(1) lookup, which is usually the difference between a brute-force and an accepted solution.

Strings & StringBuilder

String s = "hello";
s.charAt(0); s.length(); s.substring(1, 3); s.toCharArray();
// Strings are IMMUTABLE — every concatenation in a loop creates a new object
StringBuilder sb = new StringBuilder();
sb.append('a').append("bc");
sb.reverse();
sb.toString();
Gotcha: building a string with += inside a loop is O(n²) overall because each += copies the whole string. Use StringBuilder for anything built incrementally.

static vs instance

Since public static void main is static, it can only call other static methods directly (no object needed). To call a non-static (instance) method, you first need new ClassName().method(). In DSA practice files this is why almost every helper method ends up static.

Two Pointers

Intuition: when the array is sorted, or you're looking for a pair/triplet meeting some condition, move two indices toward each other (or both forward) instead of nesting loops. Each pointer moves at most n times total, so it collapses an O(n²) brute force into O(n).

int left = 0, right = arr.length - 1;
while (left < right) {
    int sum = arr[left] + arr[right];
    if (sum == target) { /* found */ break; }
    else if (sum < target) left++;
    else right--;
}

Commonly asked

  • Two Sum (sorted array)
  • Container With Most Water
  • Valid Palindrome
  • Remove Duplicates from Sorted Array (in-place)
  • 3Sum (sort + fix one, two-pointer the rest)

Sliding Window

Intuition: maintain a window [left, right], expand right to grow it, shrink from left when a constraint is violated. You just built this live for Longest Substring Without Repeating Characters — the core discipline is keeping your auxiliary structure (Set/Map) in sync with exactly what's inside [left, right].

Commonly asked

  • Longest Substring Without Repeating Characters ✅ (you solved this today)
  • Maximum Sum Subarray of Size K
  • Minimum Window Substring
  • Longest Substring with At Most K Distinct Characters
Gotcha you hit live: forgetting to remove the evicted character from your tracking Set when shrinking the window — it silently keeps counting characters that are no longer in range.

Hashing

Intuition: trade memory for speed — a HashMap/HashSet turns "have I seen this value / how many times" into O(1). Default to this whenever brute force means an inner loop scanning for a match.

Commonly asked

  • Two Sum (unsorted array)
  • Group Anagrams (map sorted-string → list)
  • First Non-Repeating Character in a String
  • Longest Consecutive Sequence
  • Subarray Sum Equals K (prefix sum + HashMap)

Kadane's Algorithm / DP Intro

Intuition: at every index, decide "extend the running subarray, or restart here?" — that's currentSum = max(arr[i], currentSum + arr[i]). Track the best answer seen so far separately in maxSum. This is the simplest possible dynamic programming: today's decision only depends on yesterday's running result.

Commonly asked

  • Maximum Subarray Sum ✅ (you solved this today)
  • Maximum Product Subarray (track both running max and min — negatives flip the sign)
  • Best Time to Buy and Sell Stock (track min price seen so far, max profit so far)

Linked List

Intuition: almost every LinkedList problem is pointer bookkeeping — draw three boxes (prev, curr, next) on paper before writing code. For cycle/middle problems, use a slow pointer (1 step) and fast pointer (2 steps): if there's a cycle, fast laps slow and they meet.

// Iterative reversal
ListNode prev = null, curr = head;
while (curr != null) {
    ListNode next = curr.next;  // save before overwriting
    curr.next = prev;
    prev = curr;
    curr = next;
}
return prev; // new head

Commonly asked

  • Reverse a Linked List (iterative + recursive)
  • Detect Cycle (Floyd's slow/fast pointer)
  • Find the Middle Node
  • Merge Two Sorted Lists
  • Remove Nth Node From End (two pointers, gap of n)
Gotcha: always save curr.next before you overwrite it, and always null-check before dereferencing — NullPointerException on .next.next is the #1 LinkedList interview slip.

Recursion & Backtracking

Intuition: write the base case first, then trust the recursive call to correctly solve the smaller subproblem (the "leap of faith") — don't try to mentally unroll the whole call stack. Backtracking is recursion plus undo: choose an option, recurse, then un-choose it before trying the next option.

void backtrack(List<Integer> path, int start, int[] nums) {
    result.add(new ArrayList<>(path));      // record current state
    for (int i = start; i < nums.length; i++) {
        path.add(nums[i]);                    // choose
        backtrack(path, i + 1, nums);          // explore
        path.remove(path.size() - 1);          // un-choose
    }
}

Commonly asked

  • Subsets / Power Set
  • Permutations
  • Combination Sum ✅ (in your repo already)
  • Generate Parentheses
  • N-Queens (harder, but a common "if time permits" follow-up)
Gotcha: forgetting the "un-choose" step means state leaks across branches and later results silently include earlier choices.

Sorting

Intuition: Merge Sort splits, sorts each half, then merges (stable, always O(n log n), needs O(n) extra space). Quick Sort picks a pivot, partitions everything smaller to its left and larger to its right, then recurses on each side (in-place, O(n log n) average, O(n²) worst case if pivots are always the smallest/largest element).

Commonly asked

  • Implement Merge Sort / Quick Sort from scratch (know both — you already have these in your repo)
  • "Why is Quick Sort worst-case O(n²)?" (bad pivot choice on already-sorted input)
  • Sort Colors (Dutch National Flag, one-pass 3-way partition)
  • Kth Largest Element (heap or quickselect)

Stacks & Queues

Intuition: reach for a stack whenever a problem is about "matching," "nesting," or "the most recent unresolved thing" (LIFO). Reach for a queue when order must be preserved (FIFO) — e.g. BFS, or processing requests in arrival order.

Deque<Character> stack = new ArrayDeque<>();
stack.push('('); stack.peek(); stack.pop(); stack.isEmpty();

Commonly asked

  • Valid Parentheses
  • Min Stack (O(1) min retrieval)
  • Next Greater Element (monotonic stack)
  • Implement a Queue using Two Stacks

Trees

Intuition: most tree problems are naturally recursive — "solve for the left subtree, solve for the right subtree, combine the results at the current node." Know the three DFS traversal orders and one BFS (level order).

void inorder(Node n){ if(n==null) return; inorder(n.left); visit(n); inorder(n.right); }
void preorder(Node n){ if(n==null) return; visit(n); preorder(n.left); preorder(n.right); }
void postorder(Node n){ if(n==null) return; postorder(n.left); postorder(n.right); visit(n); }

Commonly asked

  • Inorder / Preorder / Postorder traversal (recursive and iterative-with-a-stack)
  • Level Order Traversal (BFS using a Queue)
  • Height / Max Depth of a Binary Tree
  • Check if a Binary Tree is Balanced
  • Search/Insert in a Binary Search Tree — O(log n) average, O(n) worst if skewed

OOP Concepts (Java)

What are the four pillars of OOP?

Encapsulation (bundle data + methods, hide internals via private fields/getters), Inheritance (a class reuses/extends another's behavior), Polymorphism (one interface, many implementations), Abstraction (expose what an object does, hide how).

Overloading vs Overriding?

Overloading = same method name, different parameters, resolved at compile time. Overriding = subclass redefines a parent's method with the same signature, resolved at runtime (dynamic dispatch).

Abstract class vs Interface?

Abstract class can hold state (fields) and partial implementation; a class can extend only one. Interface is a pure contract (Java 8+ allows default methods); a class can implement many interfaces. Use an interface for "can-do" capabilities, abstract class for shared state/behavior across closely related classes.

Can you override a static method?

No — static methods are resolved at compile time based on the reference type ("method hiding," not overriding).

DBMS / SQL

Types of SQL joins?

INNER JOIN — only matching rows in both tables. LEFT JOIN — all rows from the left, matched rows from the right (nulls if none). RIGHT JOIN — mirror of left. FULL OUTER JOIN — all rows from both, matched where possible.

What does an index actually do?

Speeds up reads (typically a B-tree) by avoiding a full table scan, at the cost of slightly slower writes (the index itself must be updated) and extra storage.

ACID properties?

Atomicity (all-or-nothing), Consistency (valid state to valid state), Isolation (concurrent transactions don't interfere), Durability (once committed, survives a crash).

When would you pick MongoDB/Firestore over MySQL? (directly relevant to your resume)

NoSQL when the schema is flexible/evolving, data is naturally document-shaped (JSON-like), or you need easy horizontal scaling. Relational (MySQL) when you need multi-row transactional integrity, complex joins, or strict schema enforcement. Be ready to justify which you used where and why, for both Texas AI and your LMS project.

Resume Deep-Dive Q&A

Predicted questions straight off your resume bullets, with a talking-point structure for each — don't memorize word-for-word, know the reasoning well enough to handle a follow-up.

Cosine ranking algorithm for candidate scoring

Walk me through how cosine similarity works and why you used it here.

Represent both resume and job description as vectors (TF-IDF or embeddings). Cosine similarity = dot(A,B) / (‖A‖·‖B‖) — it measures the angle between vectors, not magnitude, so a short resume and a long one can still score fairly on content overlap alone. Range is -1 to 1 (0 to 1 for non-negative vectors like TF-IDF).

Why not Euclidean distance instead?

Euclidean distance is sensitive to vector length/magnitude — a resume with more words would be penalized purely for being longer, even with identical relevant content. Cosine similarity normalizes that away.

Finetuned BERT for resume parsing

What does "finetuning BERT" actually involve, and why not use it out of the box?

Pretrained BERT has general language understanding from large-scale unsupervised training. Finetuning adds a task-specific head (e.g. token classification/NER for skills, titles, dates) and continues training on your labeled resume data, typically with a small learning rate and few epochs to avoid "catastrophic forgetting" of the pretrained knowledge. Out-of-the-box BERT doesn't know your specific extraction schema.

How did you evaluate the parser's quality?

Have a concrete answer ready — precision/recall/F1 on a held-out labeled set is the expected framing if you measured it; if you didn't formally measure it, be honest and explain what you'd add.

FastAPI

Why FastAPI over Flask or Django?

Native async support (good for I/O-bound ML inference calls), automatic request validation + serialization via Pydantic, and auto-generated OpenAPI/Swagger docs with less boilerplate than Flask.

AWS (EC2, S3)

What's the difference between EC2 and S3, and how did you use them?

EC2 = virtual compute instances (where your app/model actually runs). S3 = object storage (files, model artifacts, static assets) — not a filesystem, accessed via API. Be ready to describe your actual deployment flow end to end.

RabbitMQ

What problem does a message queue solve?

Decouples producer and consumer so they don't need to be online/fast at the same time — useful for async/long-running work (like ML inference) without blocking the request thread, plus built-in retry/buffering under load.

React (front-end)

What's the Virtual DOM and why does it help performance?

React keeps an in-memory representation of the UI, diffs it against the previous version on state change, and only patches the real DOM where it actually changed — avoiding expensive full re-renders.

NeuroSpectra (SVM, 99.98% accuracy)

99.98% accuracy is unusually high — how do you know the model isn't overfitting?

Video conferencing app (Agora-RTC)

How does real-time video actually get from one user to another?

WebRTC-based peer connections (Agora manages the signaling + media routing/SFU layer) — you don't need deep protocol internals, but be able to explain: signaling to establish a connection, then peer-to-peer (or via a media server) audio/video streaming, plus what Agora specifically handled for you vs. what you built (chat, screen share, anonymous sign-in).
